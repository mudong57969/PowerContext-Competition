# 业务规格：任务状态筛选

版本: v2
状态: 生效中
来源: minimax 赛道最小业务样例
取代: v1

## 1. 背景

一张固定的任务表，表中每条记录带有 `status` 字段。业务只提供「按状态筛选」这一个动作。

## 2. 数据

固定 5 条记录，状态取值只有 `open` 与 `closed`：

| task_id | status |
| --- | --- |
| T-001 | open |
| T-002 | open |
| T-003 | closed |
| T-004 | open |
| T-005 | closed |

## 3. 功能需求

- **R1** 记录集合固定，不随调用变化。
- **R2** 传入合法状态（`open` / `closed`）时，精确返回该状态的记录。
- **R3** 不传状态时，返回全部记录（此行为不变）。
- **R4** 状态取值不在合法集合内时，返回空结果，不抛异常。
- **R5** **状态入参的首尾空白必须被忽略**：`status=" open "` 与 `status="open"`
  必须返回相同结果。空白归一化只作用于**入参**，不修改记录自身的 `status` 字段，
  也不改变大小写语义（`"OPEN"` 不等于 `"open"`）。

## 4. 验收标准

- **A1** 不传状态 → 返回 5 条记录。
- **A2** `status="open"` → 返回 3 条记录（T-001、T-002、T-004）。
- **A3** `status="closed"` → 返回 2 条记录（T-003、T-005）。
- **A4** `status=" open "` → 与 `status="open"` 结果完全相同（3 条记录）。
- **A5** `status=" closed "` → 与 `status="closed"` 结果完全相同（2 条记录）。

## 5. 范围外

- 状态的持久化、状态与外部系统的同步。
- 分页、排序、模糊匹配。
- 记录自身 `status` 字段的清洗或改写。
